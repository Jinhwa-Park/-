# 레시피 가격 측정기

도와줘요 셰프님!의 실험용 견적 도구. 기존 메뉴 가격표에서 찾지 못한 요리에 대해, 메뉴명과 인분을 입력하면 재료비·작업시간·인건비·포장비를 합산해 주문 금액을 제안한다.

## 견적 방식

1. 등록된 레시피가 있으면 기준 분량을 사용한다.
2. 처음 보는 메뉴는 조리 유형을 찾는다. 예를 들어 새우볶음밥은 볶음밥의 밥·채소와 볶는 작업시간을 가져오고, 새우 사용량과 단가를 별도로 적용한다. 소고기볶음밥 가격에 새우를 덧붙이면 고기가 이중 계산된다.
3. 소량 양념은 같은 조리 유형의 1인분 양념비 중앙값으로 계산한다. 들깨·크림처럼 메뉴를 특징짓는 재료는 별도로 산정한다.
4. 주문 작업시간에는 한 번 드는 준비 시간과 팬이나 냄비 용량에 따라 반복되는 조리 작업을 반영한다.
5. 조리 유형이나 핵심 재료를 식별하지 못하면 견적을 보류하고 이유를 표시한다.

**주문 오퍼(원) = 식재료비 × (1 + 재료비 가산율) + 작업시간(분) ÷ 60 × 요리사 시급 + 포장비**

가산율은 실험 설정값이다. 업계 통계의 매출 대비 식재료비 비중과는 분모가 다르다. 기본값으로 사용하는 시급·가산율·용기 단가와 예제 식재료 단가는 모두 시연용 가정이다.

## 실제 데이터 연결에 필요한 자료

| 항목 | 확보할 값 |
| --- | --- |
| 레시피 | 기준 인분, 재료별 사용량, 구매 상태와 중량 환산 근거 |
| 식재료 단가 | 품목·규격, 구매 단위, 가격, 조사일, 지역, 출처 |
| 양념비 | 같은 조리 유형에서 별도 계상한 주재료를 제외한 1인분당 양념비 표본 |
| 작업시간 | 주문마다 한 번 드는 시간, 1회 조리 용량, 한 번 더 조리할 때 늘어나는 직접 작업시간 |

자료 후보는 [식약처 조리식품 레시피](https://www.data.go.kr/data/15060073/openapi.do), [aT 주요 채소류 일일가격](https://www.data.go.kr/data/15087352/fileData.do)이다. 실제 요리사 견적과 비교할 때는 재료비, 작업시간, 최종 제안 금액을 따로 검증한다.

## 실행

Python 3에서 압축을 푼 폴더로 이동해 실행한다. 표준 라이브러리만 사용한다.

```sh
python3 cli.py 새우볶음밥 3 --extra 새우 --extra-grams 100 --containers 3
python3 cli.py 전복리조또 2
python3 -m unittest -v
```

첫 명령은 주문 전체에 새우 100g을 추가한다. 인분마다 100g을 추가하려면 `--per-serving`을 붙인다. 출력의 `lines`는 재료별 중량과 금액, `minutes`는 직접 작업시간, `total`은 주문 전체 제안 금액이다. 전복리조또처럼 미등록 재료가 들어오면 `review`와 사유를 반환한다.

예제 데이터의 조리 유형은 볶음밥·수제비·덮밥·리조또이다. 이름에서 등록된 재료 표현과 조리 유형을 조합하는 방식이며 외부 API 호출은 없다. 강남 메뉴 기준표·공공 가격 DB를 아직 연결하지 않았으므로 출력 금액은 계산 방식 확인용이다.
